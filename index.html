PREPARED FOR LINO

Hunter's field guide

Claude Code from first install to a live resume website, written for an orc hunter with a mechatronics degree and an MBA.

Welcome, Lino. This is a wiki, so skip around. Each page covers one thing, the sidebar groups them, and the search box finds any word. Tick the quest box at the bottom of a page when you have done it. Your progress stays in your browser.

You will finish with Claude Code running on your machine, a clear picture of how context, memory, models and effort work, and a resume website that reads its content from a GitHub Gist. That site is your hello world.

How the guide is laid out
Base Camp gets you installed and through a first session. The Quiver covers context, handoffs and memory. The Toolbox covers models, effort and the extension features. The Quest builds the resume site. Side Quests and Reference are for later.

BASE CAMP

Quest 1: Gear up

You need five things before the first pull: Node.js, Git, a code editor, a GitHub account, and a Claude plan that includes Claude Code. Everything here is free except the plan.

  1. Node.js LTS
    Go to nodejs.org and click the LTS button. Run the installer with the defaults. Claude Code's npm package needs Node 22 or newer, and the current LTS meets that.
  2. Git for Windows
    Go to git-scm.com and install with the defaults. This gives you Git Bash, a terminal that behaves the same as on Mac and Linux. Claude Code can run without it on Windows, but the Bash tool works better with it.
  3. VS Code
    Go to code.visualstudio.com. Tick every box on the "Additional Tasks" screen, especially Add to PATH, so you can type code . in any folder.
  4. GitHub account and the GitHub CLI
    Make a free account at github.com. Then install the CLI from cli.github.com. It is called gh, and the resume project uses it to create your gist.
  5. A Claude plan
    Claude Code needs Pro, Max, Ultra, Team, Enterprise or a Console account. The free claude.ai plan does not include it. Sign up at claude.ai.

Open a new Git Bash window and check each tool.

VERIFY EVERYTHING
node --version      # v22 or higher
npm --version
git --version
gh --version
Mac or Linux
The same tools apply. Use Homebrew if you have it (brew install node gh git), and use the Terminal app wherever this guide says Git Bash.

BASE CAMP

Quest 2: Install Claude Code

On this page

Two routes work. Because you are already installing Node, the npm route keeps everything in one toolbox, so it is the main path here. The native installer is what Anthropic recommends and it updates itself, so it is a fine alternative.

Route A: npm (matches the rest of this guide)

GIT BASH OR POWERSHELL
npm install -g @anthropic-ai/claude-code@latest

Never put sudo in front of that command on Mac or Linux. If npm complains about permissions, fix your npm prefix or use route B. To update later, run the same command again.

Route B: native installer (no Node needed for Claude Code itself)

POWERSHELL (NO ADMIN NEEDED)
irm https://claude.ai/install.ps1 | iex

Winget also works: winget install Anthropic.ClaudeCode.

Log in and check

ANY TERMINAL
claude --version
claude doctor
claude

claude doctor prints a read-only health report. Running plain claude opens a browser tab so you can sign in with the account that has your plan. If claude is "not found", close the terminal and open a new one so it picks up the new PATH.

Run it from a project folder
Claude Code works on whatever folder you start it in, so always cd into the project first. Never start it in your Downloads folder or your home directory.

BASE CAMP

Quest 3: Your first hunt

On this page

A session is a loop. You describe a goal, Claude reads files and proposes changes, you approve or redirect, and it carries on. Treat Claude as a pet that attacks whatever you point it at, so aim carefully.

START A PRACTICE PROJECT
mkdir hello-claude
cd hello-claude
git init
claude

Try these prompts in order. Each one shows a different habit.

  1. Look around
    Ask: "What is in this folder, and what could we build here?" Claude reads before it acts.
  2. Make something small
    Ask: "Create a single HTML page that says hello, in the style of a Horde quest log." You will see Claude ask permission before writing a file.
  3. Change it
    Ask: "Make the title bigger and add today's date." Claude edits the file in place.
  4. Undo
    Press Esc twice with an empty prompt to open the rewind menu. You can roll back the conversation, the code, or both.

Permission modes

Press Shift+Tab to cycle modes. Manual asks before each edit. Accept edits lets file changes through while still asking about commands. Plan mode lets Claude read and think but not change anything. Type /plan to jump straight into plan mode.

Use plan mode first on anything big
Ask for a plan, read it, fix the parts you disagree with, then let Claude build. A bad plan is cheap to change. A bad build costs context and time.

Handy habits

  • Mention files with @, for example "look at @resume.json".
  • Give Claude a way to check its work: "run the page and tell me if the console shows errors".
  • One task per session. When the task is done, start fresh.

THE QUIVER

Context: your quiver

On this page

A hunter has a limited quiver. Claude has a limited context window. Everything in the conversation counts against it: your messages, Claude's replies, every file it reads, every command output. When it fills, older detail gets squeezed out or summarized and quality drops.

What eats context

  • Files Claude reads, especially large ones
  • Long command output such as test logs and build logs
  • Web pages and search results
  • Instruction files and connected tools, which load at the start of every session
  • Long back-and-forth when you change direction repeatedly

Commands for managing it

CommandWhat it does
/contextShows how full the window is as a colored grid. Add all for more detail, including what your memory files and connected tools cost.
/compactSummarizes the conversation to free space. Add instructions to steer it, for example /compact keep the decisions and the file list.
/clearStarts a new conversation with empty context. Give it a name to label the old one.
/resumeReturns to an earlier conversation, by name or from a picker.
/rewindRolls the code and the conversation back to a checkpoint. Esc twice does the same.

Habits that save arrows

  • Start a new session for each task. Finishing a feature and starting an unrelated one in the same thread wastes space.
  • Ask for exploration through a subagent when the answer needs a lot of reading. The subagent reads the files in its own window and sends back a short summary.
  • Put stable rules in CLAUDE.md once instead of repeating them in chat.
  • Paste only the part of a log that matters.

THE QUIVER

Handoffs and reset thresholds

On this page

These are working rules of thumb, not hard limits. Quality tends to slip well before the window is completely full, so reset on a schedule instead of waiting for trouble.

Context usedWhat to do
Around 100k tokensStart planning your exit. Finish the step you are on, stop starting new threads, and decide what the next session needs to know.
Around 200k tokensReset now. Write the handoff, then /clear or open a new session. Do not push on.

Run /context to see where you are. If you use a 1M-context model, the habit still holds. A longer window gives you room, but a focused session still works better than a bloated one.

The handoff routine

A handoff is a short note that lets a fresh session pick up where this one stopped. Ask Claude to write it before you reset.

PROMPT TO USE AT THE END OF A SESSION
Write HANDOFF.md for the next session. Include:
1. Goal and current status in two sentences
2. What is done and what is left, as a checklist
3. Decisions we made and why
4. Files that matter, with one line each
5. Commands to run and the last result
6. Open problems and my next prompt
Keep it under 60 lines. Facts only.
PROMPT TO START THE NEXT SESSION
Read HANDOFF.md and @CLAUDE.md, tell me the plan in three lines,
then wait for my go-ahead.

Handoff versus compact

Use /compact when you want to keep going in the same conversation and the thread is still healthy. Use a handoff plus /clear when the task is changing, the thread has wandered, or you passed the 200k line. The handoff file survives anything, including a closed laptop, so it also works across days.

Keep it out of Git
The starter project already lists HANDOFF.md in .gitignore. Handoffs are working notes, not part of the project.

THE QUIVER

Memory: CLAUDE.md and auto memory

On this page

Every session starts blank. Two things carry knowledge across sessions: the instructions you write, and the notes Claude writes about you. Together they are your memory system.

CLAUDE.md, the rules you write

Claude reads these files at the start of each session. They load in layers, from broad to specific, and combine instead of overriding each other.

WhereScope
~/.claude/CLAUDE.mdYou, in every project. Your background, tone and habits.
./CLAUDE.md or ./.claude/CLAUDE.mdThis project, shared through Git. Commands, conventions, rules.
./CLAUDE.local.mdYour private notes for this project. Add it to .gitignore.

Run /init inside a project and Claude drafts a CLAUDE.md from what it finds. If one exists, it suggests improvements instead of overwriting. Run /memory to open any of these files, and to see what is loaded.

What belongs in it

Build commands, how to run tests, folder layout, naming rules, things Claude must never do, and your preferences. Keep each file under about 200 lines. Longer files use more context and get followed less closely.

A STARTER ~/.claude/CLAUDE.md FOR YOU
# About me
Mechatronics engineer with an MBA in logistics. Background in SAP
master data, Excel analysis and process improvement at Stellantis
and FORVIA. Newer to programming, so explain new ideas with
supply chain analogies and show me the command before running it.

# How to work with me
- Plan first on anything touching more than two files.
- Never invent facts, numbers or dates in my resume or CV.
- Prefer plain Node.js with no dependencies.

Auto memory, the notes Claude writes

Auto memory is on by default. When you correct Claude or state a preference, it can save a note on its own. The notes live under ~/.claude/projects/<project>/memory/, with a MEMORY.md index that loads at the start of each session. You can ask directly: "remember that I use Git Bash on Windows". Turn it off in /memory or with CLAUDE_CODE_DISABLE_AUTO_MEMORY=1.

Memory is advice, not enforcement

Claude treats these files as context. It follows them well but not perfectly. For a rule that must never break, such as "never run this command", use a hook or a permission rule, covered on the Toolbox pages.

Check what is loaded
If Claude ignores a rule, run /context all and look under Memory files. A rule in the wrong folder never loads.

TOOLBOX

Models and effort

On this page

Pick the cheapest setup that does the job well. A hunter does not use the big gun on a boar. Two dials matter: which model, and how hard it thinks.

The models

AliasUse it for
haikuQuick, mechanical work: renaming, formatting, simple edits, summarizing a file. Fastest and cheapest.
sonnetDaily coding: building features, fixing bugs, refactors, most of your resume site.
opusHard reasoning: architecture, tricky bugs, reviewing a whole project, deciding between designs.
opusplanOpus while in plan mode, then Sonnet to carry out the plan. A good default for big tasks.
fableThe hardest and longest-running work, when the docs say your plan offers it.

Add [1m] for a 1M-context variant, for example opus[1m]. On the Anthropic API, opus, sonnet and haiku currently point at Opus 5.5, Sonnet 5.5 and Haiku 5.5.

Switching

MODEL COMMANDS
/model              # open the picker
/model sonnet       # switch and save as your default
claude --model haiku

In the picker, Enter saves your choice as the default and s changes only the current session.

Effort: how long it thinks

Effort sets how much reasoning Claude spends before answering. The levels are low, medium, high, xhigh and max. Set it with /effort high, or /effort auto to clear it. The docs list medium as the default for the 5.5 models. max lasts for the current session only.

LevelWhen
lowTypos, renames, "what does this line do"
mediumNormal building and editing
highBugs you cannot explain, changes touching several files
xhigh or maxDesign decisions, security review, anything where a wrong answer is expensive

Matching tool to job

JobModel and effort
Fix a typo in the resume texthaiku, low
Add a new section to the sitesonnet, medium
Debug why the gist will not loadsonnet, high
Plan the structure of a portfolio projectopusplan or opus, high
Review the finished project before you share itopus, high or xhigh

Higher effort and bigger models spend your plan's usage faster. Run /usage to see where you stand. When a cheaper setup stalls twice, move up one step instead of re-asking the same thing.

Models for helpers

Subagents have their own model setting, so a research helper can run on haiku while your main session runs on sonnet. See the next page.

TOOLBOX

Skills, subagents, hooks, MCP, plugins

On this page

Claude Code has five ways to extend it. Each solves a different problem, and knowing which to reach for saves a lot of trial and error.

FeatureUse it when
CLAUDE.mdYou want a rule or fact loaded in every session
SkillYou have a repeatable workflow or reference Claude should load only when relevant
SubagentA task needs its own context window, or should run in parallel, and returns a summary
HookSomething must happen automatically on every matching event, with no exceptions
MCPClaude needs to reach an outside service such as GitHub, a database or a calendar
PluginYou want to package skills, hooks, subagents and MCP servers so you can reuse or share them

Skills

A skill is a folder with a SKILL.md file. Claude loads its short description at the start and the full text only when the task matches, or when you type /skill-name. Personal skills live in ~/.claude/skills/<name>/, project skills in .claude/skills/<name>/.

.claude/skills/tailor-resume/SKILL.md
---
description: Tailor resume.json to a pasted job posting without inventing facts
disable-model-invocation: true
---
Compare the job posting I paste with resume.json. List the matching
skills, then propose reworded bullets that use the posting's own
terms. Never add experience I do not have. Ask me for any missing number.

With disable-model-invocation: true, the skill runs only when you type it. Use that for anything that changes or publishes something.

Subagents

A subagent is a helper with its own context window. It does the reading and sends back a summary, which protects your quiver. Define one as a markdown file in .claude/agents/ or ~/.claude/agents/, or just ask: "use a subagent to find every place the site reads the gist URL".

.claude/agents/reviewer.md
---
name: reviewer
description: Reviews changes for mistakes before I commit
tools: Read, Glob, Grep
model: sonnet
---
Review the current changes. Report real problems only, with file
and line. Do not edit anything.

Hooks

A hook runs a script or command on an event, such as before a tool runs or after a file is edited. Claude does not decide whether to run it. That makes hooks the right place for rules that must hold, like blocking edits to a protected file.

MCP

MCP servers connect Claude to outside services. Manage them with /mcp. They cost context, because their tool names load at the start. Check the cost with /context all. Install only the ones you use, prefer read-only access, and check who made each server before you connect it.

Plugins

A plugin bundles several of the above into one installable unit. Open /plugin to browse. Plugin skills are namespaced, for example /my-plugin:review.

TOOLBOX

Artifacts

On this page

An artifact is a live web page that Claude publishes from your session to a private link on claude.ai. This guide you are reading is one. You ask in plain language and Claude writes the page, publishes it, and prints the link.

How to use them

  • Ask: "make an artifact that explains my resume project as a diagram".
  • To change one, ask Claude to revise it. It republishes to the same link.
  • /artifacts lists yours. Ctrl+] reopens the latest one.
  • Sharing is controlled from the page header. On Pro and Max the only option is a public link that anyone can open, so keep personal data off pages you share.

Limits to know

  • Needs a Pro, Max, Ultra, Team or Enterprise plan and a session signed in with /login. An API key alone cannot publish.
  • The page source is HTML or Markdown, under 16 MiB, and it has no backend.
  • A page cannot start downloads or open the print dialog, so artifacts suit reading and interacting, and a PDF suits printing.

Artifact, gist or GitHub Pages

ToolBest for
ArtifactA polished page you want Claude to build and revise, shared by link
GistA single file or small set of text files, with history, that code and sites can read
GitHub PagesA permanent website at your own address, built from a repository

Your resume project uses all three ideas together: the gist holds the data, Pages serves the site, and an artifact is a quick way to prototype a design before you commit to it.

THE QUEST

Quest 4: The resume website

On this page

Your hello world is a resume site that reads its content from a GitHub Gist. It touches nearly everything in this guide: a real project folder, a CLAUDE.md, plan mode, a connected service, a deploy, and a loop for updating it.

How it fits together

THE FLOW
resume.json  --publish-->  GitHub Gist  --fetch-->  your website
(on your PC)               (the data)               (GitHub Pages)

You edit resume.json. One command copies it to a gist. The website downloads the gist when someone opens the page and draws it. Edit the gist and the site updates in a few minutes, with no redeploy.

Why a gist works here

Raw gist URLs allow browsers on other sites to fetch them, so a static page can load the data directly. They cache for about five minutes. A gist also keeps a revision history of every edit, which is handy for a resume.

What is in the starter

FileJob
resume.jsonYour resume as data. Already filled in from your LinkedIn profile.
docs/The website: HTML, CSS and a short script.
bin/resume.mjsThree commands: check, serve and publish. Plain Node, no dependencies.
CLAUDE.mdProject memory, including a rule to never publish without asking.
.gitignoreKeeps HANDOFF.md and private files out of Git.

Jake will send you the starter folder. If you would rather have Claude build one from scratch, the next page has a prompt for that.

Public or secret

A public gist is listed on your GitHub profile and anyone can find it. A secret gist is unlisted, but anyone with the link can read it. Since the point is a resume that employers see, public is fine. Either way, keep your phone number and home address out of resume.json. Use an email address and your LinkedIn link.

THE QUEST

Build it step by step

Work through these in order. Every prompt is meant to be pasted into Claude Code from inside the project folder.

  1. Open the project
    Put the starter folder somewhere like Documents, then cd into it and run claude. Ask: "Read CLAUDE.md and README.md and explain how this project works in five lines."
  2. Log in to GitHub
    Run gh auth login and follow the browser prompts. Then npm run check. All four lines should say ok.
  3. Preview the site
    Run npm run dev and open http://localhost:3000. You should see your resume. Press Ctrl+C to stop it.
  4. Make it yours
    In plan mode (Shift+Tab, or /plan), ask: "Plan the changes needed so resume.json says what I want. Ask me questions first. Never invent a number." Answer honestly, approve the plan, and let Claude edit resume.json.
  5. Dry run the publish
    Run npm run publish:gist -- --dry-run. It prints what it would do and sends nothing. Check the visibility line.
  6. Publish the gist
    Run npm run publish:gist. It creates the gist, saves its id in resume.config.json, and points docs/config.js at it.
  7. Put it on GitHub Pages
    Ask Claude: "Create a GitHub repository for this folder, commit everything, and push. Ask me before the push." Then in the repository go to Settings, Pages, and deploy from branch main, folder /docs. Your site appears at https://<your-username>.github.io/<repo-name>/.
  8. Update later
    Edit resume.json, run npm run publish:gist, commit if you changed the site files. The gist updates in place, so the link never changes.
IF YOU WANT CLAUDE TO BUILD IT FROM SCRATCH
Create a resume website in this empty folder, Node 22 only, no
dependencies. Requirements:
1. resume.json holds all content (basics, experience, education, skills)
2. docs/ has index.html, style.css and app.js that fetch the data
   from a gist raw URL stored in docs/config.js, with a fallback to
   a local resume.json, and render it using textContent only
3. bin/resume.mjs with check, serve and publish commands; publish
   uses gh api to create or update a gist and supports --dry-run
4. a CLAUDE.md that says never to publish without asking
Plan first and wait for my approval before writing files.
Why the dry run exists
Publishing creates something on the internet under your name. Always look at what is about to happen first. The starter's CLAUDE.md tells Claude to ask before publishing, and that habit belongs in every project you make.

Stretch goals

  • Add a "Projects" section that links to your side quests.
  • Add a print-friendly layout so the page saves as a clean PDF from your browser. The starter already has print styles.
  • Make a Spanish version that reads a second gist file, resume.es.json.

THE QUEST

Make the resume itself stronger

On this page

The site is only as good as the content. Claude is very good at tightening text and asking the right questions, and very willing to invent things if you let it. Your job is to keep it honest.

Things worth fixing in the current resume

  • Duplicates. The profile lists the SMIA internship twice, the translator job twice, and the same degrees under different names. The starter already merges these. Check the merged version is right.
  • Duties versus results. Most bullets say what you did, not what changed. Add numbers where you have them: how many part numbers, how much validated cost saving, how many people you onboarded, how many weeks of data you owned.
  • Level 2 to Level 3. Recruiters outside Stellantis will not know what that means. Explain the process in one plain sentence.
  • A target. Pick the roles you want, such as supply chain analyst, master data specialist, process improvement or operations analyst. Then the summary and skills can speak to them.

Prompts that work

ASK IT TO INTERVIEW YOU
Read resume.json. For each job, ask me up to three questions that
would uncover a measurable result. Wait for my answers. Then
propose rewritten bullets. Do not add anything I did not say.
TAILOR TO A JOB POSTING
Here is a job posting: <paste it>. Compare it with resume.json.
Show me which of my real skills match, which requirements I lack,
and propose reworded bullets using the posting's language. Keep
everything true. Save the tailored version as resume.<company>.json.
PRACTICE THE INTERVIEW
Act as a hiring manager for the posting I pasted. Ask me one
question at a time, about my real experience. After each answer,
tell me how to make it clearer and more specific.
The honesty rule
Never let a model add a skill, a number or a job title you cannot defend in an interview. Put that rule in your CLAUDE.md, as the starter does.

SIDE QUESTS

Portfolio side quests

On this page

Your strongest story is an engineer who understands how parts, costs and data move through a supply chain. Small projects that show you can also build the tools around that story set you apart. Use fake or public data only. Never use real company data from Stellantis or FORVIA.

QuestWhat it shows
Cost-saving trackerA dashboard that checks savings calculations against a part list and flags mismatches. Mirrors your Value Optimization work with invented data.
Master data checkerA script that reads a spreadsheet of part numbers and suppliers and flags duplicates, missing fields and format errors.
Shipment trackerA page that reads a list of shipments and shows status, delays and late orders.
Warehouse layout plannerA small tool that places machines on a grid and checks clearances. Builds on your AutoCAD and relocation experience.
Spreadsheet to PythonTake one Excel analysis you know well, rebuild it in Node or Python, and write up what got faster.

How to start any of them

A FIRST PROMPT FOR ANY SIDE QUEST
I want to build <project> as a portfolio piece. Use only invented
sample data. Plan first: ask me what a recruiter should learn from it,
propose a file layout and a first milestone I can finish in an
evening, then wait for my approval.

Each side quest gets its own folder, its own CLAUDE.md, and a short write-up on your site. A recruiter who sees three small, working, well-explained projects learns more than from a long skills list.

Use Claude for the job hunt itself

  • Ask Claude to build a simple tracker of roles, dates and follow-ups as a spreadsheet or a small page.
  • Ask it to draft a short, specific note to a recruiter, then rewrite it in your own voice.
  • Ask it to turn your day-to-day work into plain stories for interviews using the situation, action and result pattern.
